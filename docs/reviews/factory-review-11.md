## (c) Remaining and new proposals, prioritized

1. **On an empty repository `init` commits the lockfile without its `package.json`, and the first wave fails with `INSTALL-FAILED`.** `bin/agentic-factory.mjs:168-172` runs `pnpm install` against the untracked `package.json` and `:218` adds only `manifest.files` plus the lockfile to the adoption commit, so `origin/main` carries `pnpm-lock.yaml` and `commands.install = pnpm install --frozen-lockfile` but no manifest (experiment (b): `?? package.json` after init; `init` prints nothing about it, the checklist says the adoption "is on origin/main"). A Developer worktree or the integration worktree from that `origin/main` cannot install: (b-wave) `[ERR_PNPM_NO_PKG_MANIFEST] No package.json found`, `INSTALL-FAILED`, exit 1. This is the documented first-hour input (`docs/getting-started.md:8`: "a fresh `git init` is fine") that round 10 made `init` accept; it now succeeds into a state whose recorded install command cannot run. Change: when `init` generated the lockfile and `package.json` is untracked (`git ls-files --error-unmatch package.json` fails), add `package.json` to the adoption commit next to the lockfile (the lockfile is derived from it); otherwise stop before committing with "commit your project files first". Add a checklist line naming any files still untracked after the adoption commit. Test: empty repo with `package.json` → `origin/main` carries `package.json` and the lockfile; `integ-wave.sh` on a reviewed task from it → `PUSHED main`. **verdict-relevant** (breaks a newcomer's first wave on a documented input; the message points nowhere).
2. **Start over without a commit: the stale bare at the hashed path is adopted, the push fails, `init` exits 0 with a dangling `origin` and armed hooks.** `bin/agentic-factory.mjs:85` skips the history probe when `HEAD` is missing, so with `existed` true (`:80`, the previous attempt's bare) `init` prints `using the existing local bare remote`, the adoption push at `:340` is rejected (non-fast-forward), `:341` returns "this branch (not pushed)" and the command exits 0 (experiments (c4), (c4b)); `origin` stays on the stale bare and `core.hooksPath` is armed, so the local `main` is unrelated to `origin/main` for everything that follows. Change: when `HEAD` is missing and the bare `existed`, require it to be empty (`git -C <bare> rev-parse -q --verify HEAD` must fail), else take the same stop path as `:87` (remove `origin`, print the remedy, exit 1); and let a failed adoption push end `init` with exit 1. Test: `init`, delete the directory, `git init` without a commit at the same path, `init` → exit 1 `different history`, `git remote` empty. **debt** (two uncommon preconditions; the failure is printed, not silent).
3. **An absolute `core.hooksPath` that reaches the worktree through a symlink is misreported as outside and the own hooks stop.** `bin/agentic-factory.mjs:298-300` compares `path.resolve(cwd, local)` with `process.cwd()`, which is the physical path, so `/tmp/...` against `/private/tmp/...` or any symlinked project directory fails the `startsWith` test; the NOTE then claims "the hooks there will not run in this repository" although they ran until `:222` overwrote `core.hooksPath` (experiment (e2)). Change: compare `fs.realpathSync` of both sides (fall back to the resolved path when `realpathSync` throws) and record `path.relative` of the real paths. Test: symlinked repo path in `core.hooksPath` with an own `pre-commit` → `hooks.mode = "merge"`, `pre-commit.own` runs. **debt**.
4. **Own mode: the arming message and the rendered protocol contradict `doctor`.** `bin/agentic-factory.mjs:192` prints the effective `git config core.hooksPath`, so with only a global value it says `core.hooksPath is /…/ghooks` while `doctor` (`:427`) says `NOT armed` (experiment (d4)); print `--local` and compare with `setup.hooksPath` as `doctor` does. `templates/docs/review-protocol.md:76` renders, right after `{{HOOK_ENFORCEMENT}}` ("The factory does not verify them."), "With the factory hooks armed (`core.hooksPath=.githooks`), `pre-push` checks every update of `main`" in own mode too (experiment (d2), rendered line 76); move that sentence into the factory/merge branch of `HOOK_ENFORCEMENT` (`bin/agentic-factory.mjs:254-256`) or render an own-mode paragraph that says the project's own `pre-push` must implement the rule. Test: `init --keep-own-hooks` with a global `core.hooksPath` → the HOOKS line says `NOT armed`; the rendered protocol has no "factory hooks armed" sentence. **debt**.
5. **`detect()` treats a relative filesystem remote as a hosted repository.** `bin/agentic-factory.mjs:44` matches only `/`, `~` and `file:`; `git remote add origin ../rel.git` yields `project.name = rel` and `project.repo = ../rel` (experiment (c5)), the hash-for-a-name problem of round 10 in a smaller form. Change: extend the test to `^(\.\.?\/|\/|~|file:)` and, when the remote is a filesystem path, record `local:<absolute path>` as `project.repo`. Test: relative remote → `project.name` = directory name. **debt**.
6. **The wave script's scratch files are fixed `/tmp` paths shared by every project and every wave on a host.** `controller/integ-wave.sh:23-47` writes `/tmp/wave-{install,merge,commit,verify,e2e,push}.log`, `controller/wave.mjs:19` decodes to `/tmp/integ-wave.sh` and tees `/tmp/wave.out`, `controller/runscript.mjs:14` likewise; two Controllers on one host (documented in `docs/server-setup.md`, "a second project on the same host") or a wave overlapping a `runscript.mjs` run overwrite each other's logs, and the failure excerpts the script prints (`tail -3 /tmp/wave-install.log`, `grep … /tmp/wave-verify.log`) can come from the other run. Change: `d=$(mktemp -d "${TMPDIR:-/tmp}/${FACTORY_PROJECT:-wave}.XXXXXX")` at the top of `integ-wave.sh` and use `$d/…`; key the two files in `wave.mjs`/`runscript.mjs` by project. Test: two waves started in two integration worktrees with different `FACTORY_PROJECT` write disjoint files. **debt**.

Not re-listed: F01 (`git -c core.hooksPath=/dev/null push` lands, (a11)), F15 (`HUSKY=0` lands, (f3); the dev spec has no install step), both recorded in `debt.md`.

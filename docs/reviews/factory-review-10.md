## (c) Remaining and new proposals, prioritized

1. **`init` fails on an empty repository and on a re-used path, and the printed remedy makes it worse.** `bin/agentic-factory.mjs:83-84` treats every failure of the first `git push -u origin <branch>` to the fresh bare as "holds a different history" and exits 1. On a repository with no commit yet (`docs/getting-started.md:8`: "a fresh `git init` is fine") the push fails because `main` has nothing to push, so a documented input now stops with a false message; the round-8 CLI handled it (k3). On a genuinely foreign bare (k2) and when a newcomer starts over at the same path (k6), `origin` is left pointing at that bare, so "remove it … then run init again" ends in `adoption commit created locally; push failed: … does not appear to be a git repository`, and because `detect()` (`:41-43`) takes the project name from `remote.origin.url`, the re-run records `project.name = app-982c41` (branches, worktrees, locks and the preview are then named after a hash). Change: skip the first push when `git rev-parse --verify HEAD` fails (the adoption commit pushes with `-u`); on a rejected push run `git remote remove origin` before exiting; in `detect()` use `basename(cwd)` when the remote URL is a filesystem path. Test: empty repo → `init` exit 0, adoption on `origin/main`, `project.name` = directory name; foreign bare → exit 1, `git remote` empty, `init` after removing the bare succeeds. **verdict-relevant** (a regression of the round-9 fix on a documented first-hour input; the wrong project name silently spreads into every branch and worktree name).
2. **`--keep-own-hooks` is accepted and `doctor` is green while the project's hooks are not armed.** `bin/agentic-factory.mjs:418-420` only checks that `<dir>/pre-commit` and `pre-push` are executable; `:218` sets no `core.hooksPath` in own mode. Experiment (g)/(n): no `core.hooksPath`, a staged secret commits, `doctor` exit 0 with `OK own hook …`. Change: in the own branch of `doctor` compare `git config core.hooksPath` with `c.hooks.hooksPath` as `:422` does, and let `init --keep-own-hooks` print `core.hooksPath` or `NOT armed`. Test: own hooks without `core.hooksPath` → `doctor` exit 1 naming the `git config` command. **debt** (extends F14; the mode is opt-in).
3. **An absolute `core.hooksPath` inside the worktree is misreported as outside and the project's own hooks stop silently.** `bin/agentic-factory.mjs:293` requires `!path.isAbsolute(p)`, so `/…/project/.hooks` prints `points outside this repository`, gets `hooks.mode = factory`, and `:218` overwrites the path (b2: `OWN-ABS-PRE-COMMIT` never runs again). Change: decide "inside" by `path.resolve(cwd, p).startsWith(cwd + path.sep)` alone and record `path.relative(cwd, p)` as the directory; for a path truly outside, say that the hooks there will not run in this repository (F16 wording). Test: absolute in-worktree path with an own `pre-commit` → `merge`, `pre-commit.own` runs. **debt**.
4. **Three document residues of the round-9 changes.** `docs/getting-started.md:30` and `docs/de/erste-schritte.md:30` still name the bare `~/.factory-remotes/<project>.git` (now `<project>-<hash6>.git`). `docs/workflow.md:217` and `docs/de/workflow.md:226` say only "`--no-verify` is forbidden" while `templates/AGENTS.md:18` and `controller/CONTROLLER.md:25` now forbid `HUSKY=0` and `core.hooksPath` changes too, and `workflow.md:6` promises agreement with `AGENTS.md`. `templates/docs/review-protocol.md:76` renders "`core.hooksPath` pointing at `{{HOOKS_DIR}}`", which reads `.husky` in the husky layout while the path is `.husky/_` (o): render `HOOKS_PATH` there. **debt**.

## (c) Remaining and new proposals, prioritized

1. **In `merge` mode the appended guardrails print their failure and the commit succeeds anyway.** `bin/agentic-factory.mjs:284-290` appends three plain `node tools/factory-guardrails.mjs …` lines to the own `pre-commit`; without `set -e` in the own hook only the last line's status counts (b1: secret, `.env.local` and dropped test all commit with exit 0 while `doctor` reports `factory guardrails wired (merge)`); after a trailing `exit 0` the lines never run (b2); in a non-shell hook they are a syntax error that blocks every commit (b3). The push gate is intact, so unreviewed code still does not reach `main`, but secrets and `.env` files do reach pushed branches and the hook's own output claims otherwise. `test/smoke.test.mjs:169-184` checks only that the own line ran and the push was rejected. Change: do not append. Move the own hook to `.githooks/pre-commit.own` (kept, committed), write the factory `pre-commit`, and let the template run the own hook first under `set -eu`: `[ -x .githooks/pre-commit.own ] && .githooks/pre-commit.own`. That survives `exit 0`, missing `set -e` and any interpreter. Test: own `pre-commit` = `#!/bin/sh\nset -e\necho OWN >&2\nexit 0`, then a staged secret → commit rejected and `OWN` printed; own hook as a node script → still runs.
2. **The adoption commit is never pushed when `core.hooksPath` already points at `.githooks`, which is every project `merge` mode exists for.** `bin/agentic-factory.mjs:300` pushes with whatever hooks are armed; `:209` sets `core.hooksPath` only afterwards, which is why a fresh repo works and the smoke test passes (its fixture never sets the config). In (b1) and (g1) the factory `pre-push` is live at push time and rejects the adoption commit; `init` prints "created locally; push failed" and the checklist says "on this branch (not pushed)" with no way out, since every later push to `main` is gated and nothing suggests writing a review file. `origin/main` then carries neither `AGENTS.md` nor the hooks: the first workers and the first wave start from the wrong `main`. Change: make this one push hook-free, `spawnSync("git", ["-c", "core.hooksPath=/dev/null", "push", "-q", "-u", "origin", branch])`, and say so in the comment above `commitAdoption`. Test: repo with `core.hooksPath=.githooks` set before `init` → `git ls-tree origin/main` contains `AGENTS.md`.
3. **In `merge` mode the merged `pre-commit` is not in the adoption commit.** `bin/agentic-factory.mjs:207` commits `Object.keys(manifest.files)`; `:280-281` keeps `.githooks/pre-commit` out of the manifest in `merge` mode, so after `init` it is a modified, uncommitted file (b1: ` M .githooks/pre-commit`; `origin/main:.githooks/pre-commit` is the own-only version). Every clone and the server checkout run without the guardrail lines until the human commits the file, which needs an ADR citation (b1: rejected without, accepted with `(ADR-0001)`); no message or document says that. Change: add `.githooks/pre-commit` to the adoption file list when `mode === "merge"` (and print `write`/`merge` for it in the same place as the other hooks). Test: after `init --yes` in merge mode `git status --porcelain` is empty and `git show origin/main:.githooks/pre-commit` contains `factory-guardrails`.
4. **In `own` mode the rendered documents still promise a gate that is not there, and `doctor` is red for good.** Rendered `AGENTS.md:34` ("the commit hook blocks changes"), `docs/review-protocol.md:76` ("With `core.hooksPath=.githooks`, `pre-push` checks every update"), `docs/dev-workflow.md:139` and `docs/de/workflow.md:143` ("Git rejects every push"), `docs/adr/0001-…:24`; the checklist is the only place that tells the truth. `doctor` (`bin/agentic-factory.mjs:372`) still demands `commit-msg` and reports `MISSING hook .githooks/commit-msg executable`, exit 1 (c), so `docs/getting-started.md:58` ("everything should be OK") never holds. Change: a `{{HOOK_ENFORCEMENT}}` template variable rendered into the "Review gate" paragraph of `AGENTS.md`, "Push enforcement" of the review protocol and the push-lock line of the guide ("enforced by the factory hooks" versus "hooks.mode = own: enforced by this project's own hooks; the factory does not verify them"); in `doctor`, for `own` require only `pre-commit` and `pre-push`. Test: `own` mode → `doctor` exit 0; rendered `docs/review-protocol.md` names `own`.
5. **A project whose hooks live outside `.githooks/` (husky, lefthook, a custom `core.hooksPath`) loses them silently.** `bin/agentic-factory.mjs:271-276` looks only at `.githooks/`, `:209` overwrites `core.hooksPath` (g2: `.husky/pre-commit` with `core.hooksPath=.husky` → `hooks.mode = factory`, nothing printed, the husky hook never runs again). Change: read `git config core.hooksPath` in `hookMode()`; when it names a directory other than `.githooks` that contains a `pre-commit`, treat that directory as the own hooks (same `merge`/`own` rule, the factory `pre-commit` calling `<dir>/pre-commit` as in item 1) and print it. Test: `.husky/pre-commit` → `init` names it, a commit after `init` still prints the husky line.
6. **Two residues of round 6.** (i) `bin/agentic-factory.mjs:160` tells a project whose declared manager is missing to "Install `<pm>` and run `agentic-factory update`", but `update` (`:319-361`) never installs or commits a lockfile and never switches `commands.install` to the frozen form (f2), so the instruction leads nowhere; say instead: "install it, run `<pm> install`, commit the lockfile and set `commands.install` to `<frozen>`" or move the lockfile step into the refresh. (ii) `docs/workflow.md:137` and `docs/de/workflow.md:141` show the literal `{{MAX_ROUNDS}}` to a reader of the factory repo (the README's "Process for people" link); one line under the title, "Placeholders in `{{…}}` are filled in by `init`; the rendered copy is your project's `docs/dev-workflow.md`", in both languages.

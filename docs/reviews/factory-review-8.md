## (c) Remaining and new proposals, prioritized

1. **Husky projects lose the review gate twice, and `doctor` is green.** (a) Husky v9 (the default of `npx husky init` since 2024) sets `core.hooksPath=.husky/_` and writes a two-line shim for *every* hook name into `.husky/_/`; the shim exits 0 when `.husky/<hook>` is absent. `bin/agentic-factory.mjs:279-285` therefore sees an own `pre-commit` *and* an own `pre-push` in `.husky/_` and chooses `own`: no factory hook, no guardrail script, `core.hooksPath` untouched (c2: a staged secret commits, an unreviewed push to `main` succeeds, `doctor` exit 0 with `OK own hook .husky/_/pre-push`, the rendered docs say the project's own hooks enforce the gate, which no file in the project does). (b) Husky v8 projects get `merge` (c), but husky's `prepare` script runs on every `npm install`/`npm ci` and sets `core.hooksPath` back to `.husky` (i2: after `npm install` the config is `.husky` again). `core.hooksPath` is one setting per repository, shared by all worktrees, so the first `npm ci` of a wave in `coordinator-integration` disarms the factory `pre-push` for the wave's own push and for every later commit; nothing prints. Change: in `ownHooksDir()`, when `<dir>/h` exists treat `path.dirname(dir)` as the own hooks directory (husky v9), and count a hook as "own" only if that file exists there; in `merge` mode with a foreign directory, do not move `core.hooksPath`: write the factory `pre-push`, `commit-msg` and `pre-merge-commit` into that directory (husky runs `.husky/<hook>` through `sh -e`, so `node tools/factory-guardrails.mjs review-gate` as a line in `.husky/pre-push` works), keep the own `pre-commit` as `<dir>/pre-commit.own` and write the factory `pre-commit` there; record the directory in `hooks.ownDir` and let `doctor` check `core.hooksPath` against it and `grep factory-guardrails` in each of those files. Tests: husky v9 layout → `hooks.mode = merge`, secret rejected, unreviewed push rejected; v8 layout with `prepare: git config core.hooksPath .husky` → after `npm install` the unreviewed push is still rejected. **verdict-relevant** (silently weakens a guardrail; `doctor` green).
2. **`merge` handles only `pre-commit`; every other own hook is dropped or shadows the factory's, and `doctor` cannot tell.** `bin/agentic-factory.mjs:283-285` decides the mode from `pre-commit` alone, `:295-302` moves only that file, and the `write` at `:174-178` keeps any other existing hook as user-owned. Consequences: an own `.githooks/commit-msg` (h5) stays in place of the factory's, so the protected-files gate is absent while `doctor:396` reports `OK hook commit-msg` (it checks existence and mode only); an own `.githooks/pre-push` without own `pre-commit` (i4) yields `hooks.mode = factory`, the own `pre-push` is kept, the review gate is absent, `doctor` reports `OK hook pre-push` and `factory guardrails wired (factory)`; in a foreign directory the own `commit-msg` (commitlint, i3) never runs again and nothing says so. Change: generalise the `.own` mechanism: for each of `pre-commit`, `commit-msg`, `pre-push`, `pre-merge-commit` present in the own directory, move or shim it to `.githooks/<hook>.own` and let each factory template run `[ -x .githooks/<hook>.own ] && .githooks/<hook>.own "$@"` first; forward hook names the factory does not ship (`prepare-commit-msg`, `post-*`) with a plain `exec` shim; decide `own` only when the own `pre-push` runs `factory-guardrails` or the user asked for it; in `doctor`, for `factory` and `merge` require `factory-guardrails` in each of `pre-commit`, `commit-msg`, `pre-push` (today only `pre-commit`, `:397`). Tests: own `commit-msg` → `AGENTS.md` change without ADR rejected and the own line printed; own `pre-push` only → unreviewed push rejected. **verdict-relevant** (`doctor` green while the push gate or the protected-files gate is absent).
3. **`update` does not migrate a project merged by the round-7 factory.** `bin/agentic-factory.mjs:360-363` splits the appended `pre-commit` into `pre-commit.own`, but the round-7 factory never recorded the merged `pre-commit` in the manifest (its `skipTemplate` excluded it), so the `write` at `:354` treats the appended file as user-owned and keeps it; the factory `pre-commit` lands in `.factory/new/`, `pre-commit.own` is created but never called and not added to the manifest (h1: a staged secret still commits with exit 0, `doctor` says `factory guardrails wired (merge)` and `own pre-commit kept`). The commit message of `cd216c2` claims "refresh splits an older appended pre-commit". Change: in the split branch set `manifest.files[".githooks/pre-commit"] = hash(cur)` before the template loop (the appended file *is* a factory product) and `manifest.files[".githooks/pre-commit.own"] = hash(own)`; print `update .githooks/pre-commit`. Test: `init` with `8222ea4`, commit the hook, `update` with HEAD → `.githooks/pre-commit` equals the template and a staged secret is rejected. **debt** (the guardrail was already weak before the upgrade; only projects adopted with `8222ea4` in `merge` mode are affected).
4. **The wave's push failure hides the reason.** `controller/integ-wave.sh:47` prints `tail -5` of the push log; the hook's first line `[factory] Push to main rejected. Commits without a passing independent review:` is cut off whenever more than two commits are listed, and in (a4) the Controller sees a bare `8ca57cf122` followed by the generic advice. Change: `grep -a -E '^\[factory\]|^[0-9a-f]{10}|^remote:|^error:' /tmp/wave-push.log | head -12` instead of `tail -5`. Test: a wave of one unreviewed task prints the `[factory] Push to main rejected` line. **debt**.
5. **Two document residues.** (i) `docs/de/workflow.md:143` ends with "Ausnahme im Alltag: Alles, was ein echtes externes System erreichen könnte, bleibt sofort ein Blocker." which has no English counterpart in `docs/workflow.md:139` (the sentence is right; add it to the English text or drop it, so both guides state the same rules). (ii) `docs/onboarding.md:29` and the `HOOKS:` line at `bin/agentic-factory.mjs:186-187` describe three modes but not what a project with husky, lefthook or a `prepare` script should expect (item 1); one sentence each once item 1 is decided. **debt**.

## (d) Verdict

Verdict: fail

Reason: items 1–4 and 6 of round 7 are fixed and hold in the experiments (the own `pre-commit` moves to `pre-commit.own` and runs first under `set -eu`, so a staged secret, an `.env` file and a dropped test are rejected behind an own hook that ends in `exit 0`; the adoption commit and its push run hook-free and `origin/main` carries `AGENTS.md`, the hooks and `pre-commit.own` with a clean status; in `own` mode the rendered documents name `hooks.mode = own` and `doctor` is green; the package-manager message and the placeholder note are in place), and the documented first wave works end to end on the real script: two reviewed tasks, the ADR-plus-dependency task, a wave after `main` moved, the rejected unreviewed and octopus waves, the reviewer-standard docs, the hand-edited merge, the wrong directory. But round 7's item 5 is only half fixed and the half that was added introduces a new hole in the very projects it targets: a husky v9 project is classified `own`, gets no factory hook at all and `doctor` reports OK while a secret commits and an unreviewed push lands on `main` (item 1a); a husky v8 project is disarmed again by the first `npm install`, including the wave's own install (item 1b); and a project with an own `commit-msg` or an own `pre-push` keeps that hook in place of the factory's, so the protected-files gate or the review gate is absent while `doctor` reports both hooks OK (item 2). Each of these silently weakens a guardrail.

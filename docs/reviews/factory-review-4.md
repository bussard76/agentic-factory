## (c) Remaining and new proposals, prioritized

1. **A wave fails for every reviewed task that touches a protected path (an ADR, `AGENTS.md`, a hook, a `package.json` dependency).** `controller/integ-wave.sh:27` concludes each merge with `git commit -m "Merge $b ($TITLE)" -m "$SUMMARY"`; `commit-msg` runs `templates/tools/factory-guardrails.mjs:94-102`, which judges the merge's staged diff (`:95`) and finds no `ADR-NNNN` in that message. Probe H (task adds an accepted ADR) and H3 (task adds one dependency, a level-2 change per `templates/AGENTS.md:31`) both end `COMMIT-FAILED`. The branch commits already passed the same hook with their own ADR reference. The only way through is the undocumented `WAVE_TRAILER` (`controller/wave.mjs:15`; probe H2 pushed with `TRAILER="Refs ADR-0002"`); `controller/CONTROLLER.md:44,61` never mention it, and the Controller's natural next step is the forbidden `--no-verify`. Change: in `integ-wave.sh`, collect the references from the merged commits (`git log --format=%B origin/$MAIN..$b | grep -oE 'ADR-[0-9]{4}' | sort -u`) and append them to the merge message; or make `protectedFiles` return early when `.git/MERGE_HEAD` exists (the merged commits were already checked, the push gate covers the rest). Test: a smoke test that waves a reviewed task carrying an accepted ADR.
2. **Without a lockfile, `init` writes an install command that cannot run, and `pnpm lint` in `pre-commit` pollutes the working tree.** `bin/agentic-factory.mjs:53` sets `npm ci` or `pnpm install --frozen-lockfile`; `controller/wave.mjs:15` passes it to every wave. Probe G2: `npm ci` in a repo without `package-lock.json` → `INSTALL-FAILED`, the wave exits 1. With pnpm present (run 1): `pnpm lint` from `static-checks` (`factory-guardrails.mjs:81`) runs `pnpm install` first, creating `node_modules/` and `pnpm-lock.yaml`; `init` does not ignore `node_modules/` (`bin/agentic-factory.mjs:178`), so the next `git add -A` commits them and the wave conflicts on `node_modules/.pnpm-workspace-state-v1.json`. `test/smoke.test.mjs:91` runs `integ-wave.sh` without `INSTALL_CMD`, which is why neither surfaced. F11 covers only the manager choice. Change: without a lockfile set `install` to `<pm> install` (no `ci`/`--frozen-lockfile`), add `node_modules/` to the ignore list when `package.json` exists, and run the smoke-test wave with `INSTALL_CMD` from the generated config.
3. **A second `init` regenerates the bundles from the default answers, not from the project's config.** `bin/agentic-factory.mjs:75-78` builds `c` from `factory.config.example.json` plus detection; with `--yes` (or Enter on every question) the user's recorded answers are gone. `:160` keeps the user-owned root config (hash mismatch) but `:168,172` overwrite `.factory/controller/factory.config.json` and `.factory/front-agent/factory.config.json` (hashes match), so `CONTROLLER.md` and the bundles diverge from `factory.config.json` (probe J2: root `Alex/3`, bundle `sascha.gering/2`). `docs/onboarding.md:3` and `bin/agentic-factory.mjs:183` call the re-run safe. The re-run also rewrites `project.repo` from `local:<bare>` to the bare path (`:42`, probe I). Change: when `hadManifest`, seed `c` and every question's default from the existing `factory.config.json`, or print "already initialised, use `update`" and stop before writing.
4. **The people's guide still says waves merge "octopus or one by one".** `docs/workflow.md:94` and `docs/de/workflow.md:98`, rendered into every project as `docs/dev-workflow.md:94` (probe D2), contradict `templates/docs/review-protocol.md:76` and `controller/integ-wave.sh:2-4`. A newcomer who reads the guide and the hook message gets two rules. Change: "one branch at a time (an octopus merge is rejected by the push gate)" in both languages.
5. **Protected-file rule and the change levels contradict each other, and any accepted ADR satisfies the hook.** `templates/AGENTS.md:31` makes a new dependency a level-2 change decided by the Controller; `:34` and `factory-guardrails.mjs:87,97` demand an `ADR-NNNN` of an accepted ADR in the commit message for dependency lists. `:101` accepts any accepted ADR, so Developers will write `ADR-0001` (probe H3 passed that way), and the protection is a formality. Change: either drop dependency lists from `PROTECTED` and leave them to the Architect's spec review, or require the referenced ADR to name the file; say which in `AGENTS.md:34`.
6. **`loadlog.sh` over-counts agents.** `controller/loadlog.sh:17` matches `pi ` anywhere in a command line; on this Mac `agents=48` includes QtWebEngine renderers (`--disable-speech-api …`). The nightly audit reads this column. Change: `pgrep -f '(^|/)(codex|claude|pi)( |$)'`, same for `vitest` and `playwright` if they ever appear as substrings.
7. **Stale references a newcomer follows into nothing.** `docs/orca.md:12` says the repo id goes into `hosts.controller.orcaRepoId` (it is `hosts.workers[].orcaRepoId`, `bin/agentic-factory.mjs:126`); `docs/orca.md:27` cites `controller/name-worker.sh`, which does not exist (`start.mjs:45` renames inline); `docs/onboarding.md:8` says the language default is `de`; `docs/onboarding.md:29` says `init` writes a `controller/` bundle (it is `.factory/controller/`); `docs/workflow.md:224` lists `mkdev`, `mktest`, … and `templates/docs/coordinator.md:73` says `templates/mk*.mjs` (it is `templates/mkspec.mjs <role>`); `docs/improvement.md:11` lacks the `cleanup` type that `controller/journal.mjs:4` accepts. Change: fix the six lines.
8. **`update` does not migrate the ignore list.** `bin/agentic-factory.mjs:258-285` never calls `appendGitignore`, so a project initialised before the round-3 fix keeps `.factory/controller/`, `.factory/front-agent/` and `.factory/server/` untracked and unignored after `update`, and the first `git add -A` sweeps them in (round-3 item 7 for existing adopters). Change: call `appendGitignore` with the same list in `initNonInteractiveRefresh`.
9. **`cleanup.mjs` reports dispatches as released when the release failed.** `controller/cleanup.mjs:68` increments `released` after `worker-release` and the `worker-abandon` fallback regardless of their result, and `:62` lists the terminals a second time, so a CLI failure between the two loops keeps workers that the first loop had already judged. The count goes into `status.md` (`CONTROLLER.md:66`). Change: count only when one of the two calls returned `"ok": true`, print the failed dispatch ids, and reuse the first terminal list per host.
10. **The smoke test's wave does not use the Controller's own environment.** `test/smoke.test.mjs:91` sets `VERIFY_CMD` and `GATE` by hand instead of what `controller/wave.mjs:15` passes (`INSTALL_CMD`, `TRAILER` from the generated config), which is why items 1 and 2 were invisible to a green suite. Change: build the env in the test from `factory.config.json` exactly as `wave.mjs` does, and add a reviewed task that adds a dependency to the two-task wave.

## (d) Verdict

Verdict: fail

Reason: the documented minimal first wave (one tiny level-1 task plus its review, lockfile present) now passes on the real script, and every probe of the review gate held (missing review branch, octopus, wave after `main` moved, reviewer-standard docs).

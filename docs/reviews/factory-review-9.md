## (c) Remaining and new proposals, prioritized

1. **A global `core.hooksPath` turns `init` outward: it renames the user's global hook, scatters the factory hooks into a stray directory, commits nothing and installs no gate.** `bin/agentic-factory.mjs:283` reads `git config core.hooksPath` without `--local`, so a user-level value (dotfiles, a global secret scanner, `~/.config/git/hooks`) becomes `setup.dir` (`:285`, layout `custom`). Then `keepOwnHooks` (`:304`) renames `~/.git-hooks/pre-commit` to `pre-commit.own` (every other repository on the machine loses that hook; principle 6, "no outward effects"), `write` (`:173`, `path.join(cwd, "/abs/path")`) puts the factory hooks under `<project>/private/…/.git-hooks/`, `commitAdoption` (`:312-313`) fails on the absolute path and returns silently, `:215` writes the global path into the local config, and the checklist tells the newcomer to commit by hand. Experiment (j): no adoption commit, a staged secret commits, `doctor` red. Change: in `hooksSetup()` read `git config --local core.hooksPath` only; if the effective value differs from the local one, say so and let the local `.githooks` override it; reject `path.isAbsolute(p)` or a `p` outside the worktree as a hooks directory (fall back to `.githooks` with a printed line); in `commitAdoption` print the `git add` error instead of returning `""`. Test: global `core.hooksPath` with a `pre-commit` → `hooks.mode = factory`, the global file untouched, `.githooks/` committed and pushed, secret rejected. **verdict-relevant** (breaks the first wave for that newcomer: `origin/main` carries nothing, no gate; and it damages files outside the repo).
2. **In a husky project the hooks are not protected files, while the rendered documents say they are.** `templates/tools/factory-guardrails.mjs:98` protects `\.githooks\/` only; round 8 moved the factory hooks into `.husky/` (`bin/agentic-factory.mjs:296`) without following. Experiment (b3): `.husky/pre-push` edited and committed without an ADR, exit 0. The rendered `AGENTS.md:34` and `docs/adr/0001-…:24` still list `.githooks/**`; `templates/docs/review-protocol.md:76` says "With the factory hooks armed (`core.hooksPath=.githooks`)" and `docs/getting-started.md:40` names `.githooks/` as the guardrails' place regardless of `hooks.dir`. Change: build `PROTECTED` from `config.hooks?.dir ?? ".githooks"` (the script already reads `factory.config.json`), escaped, plus `.githooks/` as before; render a `{{HOOKS_DIR}}` into `templates/AGENTS.md:34`, the ADR and the review protocol instead of the literal `.githooks`. Test: husky v9 layout → a change to `.husky/pre-push` without ADR is rejected. **verdict-relevant** (silently weakens a guardrail in exactly the layout round 8 added).
3. **The factory's own `pre-merge-commit` is mistaken for a project hook on every first `update` or refresh in `merge` mode.** `ownHookFiles` (`:288`) recognises factory hooks by the string `factory-guardrails`, which `templates/.githooks/pre-merge-commit` does not contain (`:5` only `exec sh "$d/pre-commit"`). `update` (`:375`) and the refresh in a fresh clone (b4) therefore rename it to `pre-merge-commit.own`, write the template again (which now runs the old copy, which runs `pre-commit`, then runs `pre-commit` itself: the static checks twice on a hand-edited merge), add a phantom entry to the manifest, leave a dirty tree, and `doctor` reports `OK own hook kept as …/pre-merge-commit.own` (experiments (m), (g), (b4)). Change: put a marker line (`# agentic-factory hook`) into every hook template and let `ownHookFiles` test for that marker or `factory-guardrails`; `doctor` should flag a `.own` file that itself contains the marker. Test: `init` then `update` on a merge-mode repo → `0 updated, 0 kept`, no `pre-merge-commit.own`. **debt**.
4. **Husky v9: no hook runs in a checkout before the first install, and `HUSKY=0` skips the gate; `doctor` is green in both cases.** `.husky/_` is gitignored and written by `husky` on install, so a fresh clone or a new worker worktree with `core.hooksPath=.husky/_` (set by `:391`) has no hooks at all until the install ran (b4: a secret commits, `doctor` exit 0; `doctor` `:408` compares the config value, `:411` checks the files in `.husky/`, nothing checks that `.husky/_/h` exists). Husky's `h` also honours `HUSKY=0` (b2: an unreviewed push with `HUSKY=0` lands on `main`). The wave is safe only because `integ-wave.sh:27` installs before merging. Change: `doctor` fails when the `core.hooksPath` directory is missing (for `layout: husky`: "run `<commands.install>` to regenerate `.husky/_`"); `templates/AGENTS.md` and `CONTROLLER.md` name `HUSKY=0` next to `--no-verify` as forbidden; the worker spec templates (`mkspec.mjs dev`) start with the install command. **debt** (F01 covers the bypass class; the worktree gap mirrors husky's own behaviour).
5. **Existing `.git/hooks/*` stop silently.** A project with hooks in `.git/hooks` (the `pre-commit` framework, lefthook's or husky 4's installer) gets `hooks.mode = factory` and `core.hooksPath=.githooks` (`:286`, `:215`); from then on those hooks never run and `init` says nothing (experiment (k)). Change: in `hooksSetup()` list executable `.git/hooks/<name>` files that are not samples and print one line (`NOTE: .git/hooks/pre-commit will no longer run; add it to .githooks/pre-commit.own`); `docs/onboarding.md:29` gets the sentence. **debt**.
6. **The local bare remote is keyed by the directory name, and the message claims it was created even when it existed.** `bin/agentic-factory.mjs:76-82`: two projects whose directories share a basename (`app`, `proj`) get the same `~/.factory-remotes/<name>.git`; the second `init` pushes into the first project's history and prints `adoption commit created locally; push failed: … ! [rejected]` (seen in my first run before the directories were renamed). Change: refuse an existing bare with foreign history (`git -C <bare> rev-parse HEAD` succeeds and is not an ancestor of the project's HEAD) and suggest `--remote-name`, or key the bare by name plus a short hash of the absolute path; print "using the existing local bare remote" when it exists. **debt**.

## (d) Verdict

Verdict: fail

Reason: all five round-8 items are fixed and hold in the experiments (husky v8 and v9 merge in place with `core.hooksPath` untouched and survive the `prepare` script; own `commit-msg` and `pre-push` become `.own` and run first, the stdin-reading own `pre-push` cannot blind the review gate; the round-7 appended `pre-commit` is split and both files join the manifest; the wave prints the `[factory]` line; the documents agree), and the documented first wave works end to end on the real script (two reviewed tasks, the ADR-plus-dependency task, a wave after `main` moved, the rejected unreviewed and octopus waves, the reviewer-standard docs, the hand-edited and the clean merge, the wrong directory, `doctor`). But two defects break or weaken the guardrails in setups a newcomer can have on day one: a user-level `core.hooksPath` makes `init` rename a file outside the repository, commit nothing and arm no hook while printing no error (item 1), and in the husky layout round 8 introduced, the hooks directory is not a protected path although the rendered `AGENTS.md` and ADR say it is (item 2).

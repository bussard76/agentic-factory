## (c) Remaining and new proposals, prioritized

1. **The first wave with two tasks fails: `integ-wave.sh` merges as an octopus and the gate rejects every octopus merge.** `controller/integ-wave.sh:18-20` merges all branches in one `git merge --no-ff --no-commit $BR` and only falls back to one-by-one merges when that merge *fails*. For two reviewed tasks the octopus succeeds (git drops each task branch because its review branch contains it, leaving `main` plus two review heads), and `templates/tools/factory-guardrails.mjs:129-131` computes the merge's "own changes" from `parents[0]` and `parents[1]` only, so the second task's files look like unreviewed changes of the merge commit. Reproduced three ways (experiment A, `integ-wave.sh`, `wave.mjs`): `octopus merge staged`, `verify PASS`, `PUSH-FAILED`. The documented wave trigger is two passed tasks (`docs/workflow.md:77`); one-task waves pass. The smoke test did not catch it because `test/smoke.test.mjs:73-77` merges sequentially instead of running the script. Change: drop the octopus path from `integ-wave.sh` (always merge one branch at a time, which the fallback already does), and make `commitFiles` fail closed on merges with more than two parents (`parents.length !== 2` → `["<octopus>"]`). Test: a smoke test that runs `integ-wave.sh` itself with `VERIFY_CMD="echo ok"` and two reviewed tasks.
2. **`capacity.mjs` counts zero workers when the Orca CLI fails.** `controller/capacity.mjs:30` turns a failed or `ok:false` `orca terminal list` into an empty set, so every Orca worker is "dead" and the calibrated cap is bypassed (experiment: two workers in `workers.json`, CLI failing, verdict `start` with `suite 0`). `controller/cleanup.mjs:20-22` treats the same failure as unknown and removes nothing. Change: return `null` when the CLI output has no `result.terminals`, and in that case count every recorded worker as live (`liveTerminals ? liveTerminals.has(w.terminal) : true` already does this once `null` reaches it). Test: the `workers.json` fixture test that `debt.md` F10 still lists.
3. **`{{PROJECT_DIR}}` ignores `projectDir`.** `bin/agentic-factory.mjs:199` builds `projectsDir/<project.name>` while `:109` records the real checkout as `hosts.workers[].projectDir` and `controller/lib.mjs:47` uses it. With a project name that differs from the directory name, the rendered `CONTROLLER.md:3,15-18` (repository path, `git pull` target, ticket glob) point at a directory that does not exist (experiment g: `…/e2e/other-name/docs/tasks/*.md` while the checkout is `…/e2e/proj`). Change: `const projectDir = ctl.projectDir ?? (…)` in `templateVars`; same for `steering/tasks.mjs` consumers through `TICKETS_LINE`.
4. **Running `init` again leaves an unpushable adoption commit.** `docs/onboarding.md:3` says running `init` again is safe, but `bin/agentic-factory.mjs:174` always calls `commitAdoption`; on a second run the hooks are armed, the commit (`.factory/manifest.json`, `factory.config.json`) passes `commit-msg` because of `ADR-0001` and is then rejected by the review gate, leaving `main` one commit ahead of `origin` with a misleading "Adopt agentic-factory (ADR-0001)" message (experiment: `adoption commit created locally; push failed`). Change: skip `commitAdoption` when `.factory/manifest.json` existed before the run and say "run `agentic-factory update`", or route a re-run to `update`.
5. **Without a lockfile `init` chooses `pnpm` and the hooks run it on every commit.** `bin/agentic-factory.mjs:46` defaults the package manager to `pnpm` when no lockfile exists, so `commands.lint` becomes `pnpm lint` and `templates/tools/factory-guardrails.mjs:74-78` runs it in `pre-commit` for every non-docs commit. With `pnpm` absent every code commit fails with `lint failed (pnpm lint)`; with `pnpm` present it installed into the working tree during the experiment's first run (`node_modules/`, `pnpm-lock.yaml` appeared and polluted the review commits until the project ignored them). Change: default to `npm` when no lockfile exists (or to the first of `pnpm`, `npm`, `yarn` found on `PATH`), and print the detected commands before question 10 so a `--yes` run shows what the hooks will execute.
6. **`wait.mjs` dies with a stack trace when `orca orchestration check` fails.** `controller/wait.mjs:16` calls `orcaJson` (`controller/lib.mjs:66-68`, `execFileSync` without a catch); a non-zero exit from the CLI (Orca not running, environment unreachable) ends the Controller's event wait at once with a Node error (experiment: exit 1 after 0 s). `front-agent/relay.mjs:19-22` catches the same failure and retries after 30 s. Change: catch in the loop, print one line (`orca check failed, retrying in 30 s`), sleep, continue until `--hours`.
7. **The bundles stay untracked and unignored.** `bin/agentic-factory.mjs:171` ignores only `.factory/new/`; `:229` commits `.factory/manifest.json`; after `init` the status shows `?? .factory/controller/ .factory/front-agent/ .factory/server/` and `docs/getting-started.md:42` does not say whether to commit or ignore them. A newcomer's first `git add -A` sweeps three bundles plus a second copy of the skills into a code commit. Change: ignore `.factory/controller/`, `.factory/front-agent/` and `.factory/server/` (they are regenerated by `update`) and say so in the table at `:42`, or commit them in the adoption commit on purpose.
8. **`loadlog.sh` counts no agents on macOS.** `controller/loadlog.sh:17` uses `pgrep -c`, which macOS `pgrep` rejects (`usage: pgrep [-Lfilnoqvx] …`), so the line `docs/getting-started.md:63` starts logs `agents= vitest= playwright=` forever. Change: `pgrep -f '…' | wc -l | tr -d ' '`.
9. **The English guide's defaults produce a German workflow guide.** `docs/getting-started.md:30` says "accept the defaults"; `bin/agentic-factory.mjs:80` defaults the human-facing language to `de`, so an English newcomer gets a German `docs/dev-workflow.md` and a Controller status "in German" (`CONTROLLER.md:92`). Change: default to `en`, or derive the default from `LANG`.
10. **Two places still say the human tests "with real data".** `docs/roles.md:7` ("tests on the preview with real data") and `site/index.html` (role card "Tests mit echten Daten auf dem Preview") contradict `docs/workflow.md:32,149` and `docs/de/workflow.md:32,153` (own environment, private copy where data is involved). Change: reword both as in `workflow.md:32`.
11. **Process rules can change on `main` without any review.** `templates/tools/factory-guardrails.mjs:27,114` exempt everything under `docs/` except `docs/adr/` and every root `*.md` except `AGENTS.md` and `ARCHITECTURE.md`; experiment G pushed changes to `docs/review-protocol.md` and `CODING_STANDARDS.md` straight to `main`. `docs/improvement.md:29` says fast-lane changes to these files run "as normal tasks with a Tester", and `templates/AGENTS.md:57` routes retro findings there. Change: exclude `docs/review-protocol.md`, `docs/coordinator.md`, `docs/architect-protocol.md` and `CODING_STANDARDS.md` from `isDocsOnly` so they need review coverage like code; document the exemption list in `docs/review-protocol.md:76`.

## (d) Verdict

Verdict: fail

Reason: item 1 breaks the newcomer's first two-task wave on the real wave path (`integ-wave.sh` and `wave.mjs` both end in `PUSH-FAILED` for two reviewed tasks); the smoke test passes because it does not run the script. Item 2 silently bypasses the calibrated worker cap when the Orca CLI fails. The review gate itself held in every other probe (missing review branch, post-review commit, smuggled file in a merge, wave after `main` moved); the known holes are the deliberate docs-only exemption (item 11) and F01.

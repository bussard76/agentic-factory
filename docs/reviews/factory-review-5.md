## (c) Remaining and new proposals, prioritized

1. **`init` on a clone of an adopted project, and `update`, never arm the hooks; the server checkout never gets them either.** `bin/agentic-factory.mjs:66-70` returns before `:192` (`git config core.hooksPath .githooks`) whenever `factory.config.json` and `.factory/manifest.json` exist, which is the case in every fresh clone because both are committed; `initNonInteractiveRefresh` (`:269-297`) never sets it; `server/2-user-setup.sh:46-49` clones and installs without it. Before round 4 the re-run went through the full `init` and set it. Probe P3: `init --yes` in a clone prints "Already initialised", `core.hooksPath` stays empty, a push of unreviewed code to `main` succeeds. The server, where every wave pushes, is such a clone; the worktrees under it share its config. Change: call `sh("git", ["config", "core.hooksPath", ".githooks"])` in `initNonInteractiveRefresh`; set it in `2-user-setup.sh` after the clone; add a smoke test that clones the bare remote, runs `init --yes` and expects the unreviewed push to be rejected; say in `docs/server-setup.md` step 5 that the clone must have `core.hooksPath=.githooks` (`doctor` already reports it).
2. **Static checks are skipped on every merge commit, including hand-edited ones.** `templates/tools/factory-guardrails.mjs:80` returns as soon as `MERGE_HEAD` exists. Probe P1: with lint failing, a plain commit is blocked, a `git merge --no-commit` plus a smuggled file commits with "static checks skipped". Every Developer and rework spec ends with "merge origin/main" (`controller/templates/mkspec.mjs:41,56`), and a conflict resolution is exactly where unlinted or untyped code is written by hand; the wave runs only `VERIFY_CMD` (`controller/integ-wave.sh:39`), which need not include lint or typecheck. Change: skip only when the staged tree is the automatic merge of the two parents (`git write-tree` equals `git merge-tree --write-tree HEAD MERGE_HEAD`), the same test the push gate uses in `commitFiles` (`:128-136`); otherwise run the checks. Test: a merge commit with an added file and a failing lint is rejected.
3. **`update` and a re-run of `init` rewrite the dates of recorded decisions.** `bin/agentic-factory.mjs:219` sets `DATE` from the clock on every run; `:274-281` overwrites every generated file whose hash still matches the manifest. Probe P5: an `update` with the clock at 2027-01-15 changed `Date:` and `Decided by:` of the accepted ADR-0001 and every "(decided by …, date)" heading in `docs/coordinator.md`, `docs/review-protocol.md`, `docs/architect-protocol.md`. The decision history is the factory's core promise ("written down the moment they are made"); after the first `update` on a later day it records the wrong day, and the human must commit a `docs/adr/` change with an ADR reference just to apply the update. Change: write `project.adoptedOn` into `factory.config.json` once in `init` and use it as `DATE` in `templateVars` (fallback: the manifest's recorded date); never take the date from the clock on a refresh. Test: `update` with a faked clock leaves the tracked docs unchanged.
4. **`integ-wave.sh` wipes any directory it is run in.** `controller/integ-wave.sh:20` runs `git clean -fdxq` before any check that this is the integration worktree; round 4 changed `-X` to `-x`, so untracked work goes too. Probe P2: run in a plain clone, `notes.txt`, `.env` and `.build/` were deleted. The script is documented for the integration worktree only (`:6`), but `CONTROLLER.md` tells the Controller to run scripts there by hand and a newcomer trying the wave from `docs/getting-started.md` has no warning. Change: refuse before `git merge --abort` unless `$(basename "$PWD")` is `coordinator-integration` or `WAVE_WORKTREE_OK=1` is set, printing the path; `wave.mjs` and the smoke test already run it in such a directory.
5. **Three documents still describe guardrails that do not exist.** `templates/docs/adr/0001-adopt-agentic-factory.md:24` (the accepted adoption ADR every project carries) and `docs/reviews.md:56` still list "root dependency lists" / "dependency lists, contracts" as protected; `docs/decisions.md:16` additionally says the push gate rejects an accepted ADR without a `Decided by` line and rejects deleting an accepted ADR, and `templates/docs/adr/0000-template.md:5` says "the push gate checks it". `factory-guardrails.mjs:93-101` only checks that the message references an accepted ADR; nothing checks `Decided by`, deletion or dependency lists. Change: fix the four lines to what `:92-101` does; if the `Decided by` and deletion checks are wanted, add them to `protectedFiles` (the ADR text is in the index) and keep the sentence.
6. **The hook's lint leaves a lockfile in every worktree of a project that had none.** Experiment (a), (c), init again: `?? pnpm-lock.yaml` after every commit, because pnpm 11 installs before `pnpm lint` (`factory-guardrails.mjs:84`). `init` ignores only `node_modules/` (`bin/agentic-factory.mjs:259`). Developers commit with `git add -A` in practice; two parallel tasks with different dependencies then conflict in a wave on a file the project never had, and `commands.install` stays the unfrozen `pnpm install` forever. Change: when `package.json` exists and no lockfile, let `init` run `<pm> install` once before the adoption commit and commit the lockfile with it, then detect the frozen install command as for any locked project; print what it did. Test: `init` in a lockfile-less repo leaves no untracked file after the first hook run.
7. **The smoke test calls the real Orca CLI.** `test/smoke.test.mjs:185-196` runs `capacity.mjs` and `cleanup.mjs --dry` with the generated config (`agents.runner: orca`) and no `ORCA_CLI_COMMAND`, so `lib.mjs:65` resolves `orca` and `orca terminal list --json` runs against the developer's Orca, contrary to `:15`. Only `:149` overrides it. Change: add `ORCA_CLI_COMMAND: "/usr/bin/false"` to that test's `env` (the assertions already accept `start|wait` and `cleanup (dry)`).
8. **The human's guide hardcodes "two review rounds".** `docs/workflow.md:137` and `docs/de/workflow.md:141` say "at most two review rounds" / "höchstens zwei Review-Runden" while `reviews.maxRounds` is configurable and `CONTROLLER.md`, `coordinator.md` and `review-protocol.md` render `{{MAX_ROUNDS}}`; in the experiment with `maxRounds: 3` the rendered `docs/dev-workflow.md` still says two. Change: `{{MAX_ROUNDS}}` in both lines (the guide is rendered through `render`, `bin/agentic-factory.mjs:171`).

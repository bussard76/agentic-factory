## (b) New findings

1. **F26 is not fixed on Linux hosts: the bracket pattern matches its own command line.** `:712`. The pattern `[b]ash loadlog.sh` avoids matching the literal `[b]ash loadlog.sh`, but the same ssh command line also carries the start command `nohup bash loadlog.sh`, which the pattern matches. Reproduced with `pgrep -a` (ancestors included) here; on procps pgrep (Linux) ancestors are never excluded, so the login shell `$SHELL -c '<string>'` always matches and the load log is never started while `start` reports ok. Fix: anchor the pattern to the daemon's own command line, `pgrep -f '^bash loadlog\.sh$'` (or `pgrep -x -f 'bash loadlog.sh'`), or start the log through a small script in the bundle so the check and the start command never share a command line; assert the behaviour in the test (run the string through `bash -c` twice and count `bash loadlog.sh` processes). Also background the command, not the and-list: `(cd ~/controller && nohup bash loadlog.sh >/dev/null 2>&1 &)` leaves a wrapper subshell with the full command line alive next to the daemon (seen locally: `bash -c mkdir -p …` with ppid 1 plus `bash loadlog.sh`). Reopen debt F26. Tag: debt (same classification as finding 3 of the previous review: remote path, no guardrail).
2. **An exited Controller terminal still counts as running.** `:578`: `terminals.some((t) => t.title === title)` ignores `status`; `capacity.mjs:31`, `cleanup.mjs:28` and `stallwatch.mjs:25` all filter `status !== "exited"`. With the stub list `[{title:"a · Controller",status:"exited"}]`, `status --json` reports `terminal:true` and `start` says "already running" instead of recreating the session. Pre-existing (the substring match had it too), now cheap to fix: add `t.status !== "exited"`. Tag: debt.
3. **`--answers` accepts answers to questions that are never asked.** `:39-46` validate against the static id list, not against `asked`. `{hosts.where:"local", hosts.remote.ssh:"ghost"}` passes `--print-questions` and `init` without a word (the value is simply unused). The previous review proposed failing on keys not in `asked` after the question loop; harmless today, but the static list must now be kept in sync with every new `ask`/`askText` id by hand. Tag: debt.
4. **Near-bare "none" markers now count as open questions.** `:596` only `none`/`nothing`/`keine` as the whole item text are empty: `- None.`, `- none yet`, `- nothing open` each become an open item and raise phase `decisions`. CONTROLLER.md prescribes `- <id>: <question…>` bullets, and the strictness was the previous review's own proposal, so this is a documented edge, not a regression; if it bites, strip a trailing `.` and accept `none/nothing/keine` followed by up to two words. Tag: debt.
5. **The new question is undocumented.** `docs/onboarding.md:13` (row 7) lists name, ssh alias and ssh config for a remote host but not the saved Orca environment name that `:186` now asks (`hosts.remote.orcaEnvironment`, default empty). START.md points the agent to onboarding.md for why a question matters; with the empty default a remote `start` fails until `hosts.workers[].orcaEnvironment` is set. One cell in EN and DE. Tag: debt.
6. **`--print-questions --answers` with an invalid value answers with stderr, not JSON.** `validateAnswers` runs in both modes (`:107`), so `init --print-questions --answers <file>` with `preview.port:"abc"` exits 1 with `--answers: "preview.port" must be a number` and empty stdout. START.md step 5 expects JSON from that call; the message is clear, nothing is written, the agent recovers by fixing the file. Consider emitting `{blocker: "…", questions: []}` as the other blockers do. Tag: debt.

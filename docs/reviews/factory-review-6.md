## (c) Remaining and new proposals, prioritized

1. **A project with its own `.githooks/pre-commit` gets no guardrail at all, silently, while every rendered document says Git enforces the gate.** `bin/agentic-factory.mjs:260-263` skips all four hooks and `tools/factory-guardrails.mjs` when `.githooks/pre-commit` exists without the string `factory-guardrails`; `:203` still sets `core.hooksPath`; nothing is printed, the checklist (`:210`) tells the human to "try a commit without [an ADR] to see the hook speak". The rendered `AGENTS.md:19-22,36`, `docs/review-protocol.md` ("Push enforcement"), `docs/adr/0001-…:24` and `docs/dev-workflow.md` all promise the review gate; `doctor` (`:332-333`) then fails forever. Experiment "own hooks": unreviewed code pushed to `main`, exit 0. Only `docs/onboarding.md:29` mentions the behaviour. A `.githooks/` directory with a lint hook is common. Change: keep the own hook but still write `tools/factory-guardrails.mjs`, `commit-msg`, `pre-push`, `pre-merge-commit`, and append the three `node tools/factory-guardrails.mjs …` lines to the existing `pre-commit` (idempotent: only when the string is absent); print one line saying so; or refuse without `--keep-own-hooks` and say what is lost. Test: init in a repo with its own `pre-commit` → the own hook still runs, the unreviewed push is rejected, `doctor` is green.
2. **`update` on every project adopted before this commit still rewrites the decision dates.** `bin/agentic-factory.mjs:231` falls back to the clock when `project.adoptedOn` is missing, and the refresh never writes `factory.config.json`, so the field is never added. Experiment 4b: `Date:`, `Decided by:` and the three handbooks move to the day of the update. The originating project is such a project. Change: in `initNonInteractiveRefresh`, when `adoptedOn` is missing, derive it once from git (`git log --diff-filter=A --format=%as -1 -- .factory/manifest.json`, fallback: the `Date:` line of `docs/adr/0001-adopt-agentic-factory.md`), persist it into `factory.config.json` and say so. Test: config without `adoptedOn`, faked clock → tracked docs unchanged, field added.
3. **A project with its own ADR 0001 records no adoption decision and gets a misnamed one.** `bin/agentic-factory.mjs:261` skips the adoption ADR, `:201` still commits `Adopt agentic-factory (ADR-0001)`, `:210` tells the human ADR-0001 is the adoption, `:262` also skips `docs/adr/0000-template.md` (so the only place that explains `Decided by:` is missing). Experiment "own ADR 0001": no adoption ADR, and because the project's ADR-0001 has no `Decided by:`, every later protected change citing it is rejected; principle 5 ("decisions are written down") is broken for the adoption itself. Change: number the adoption ADR as the next free number (scan `docs/adr/` for the highest `NNNN`), render `{{ADOPTION_ADR}}` into the commit message, the checklist and the ADR's "Consequences"; always write `0000-template.md` when it is absent (the "directory non-empty" condition also depends on the order `walk()` yields the two template files, which `readdirSync` does not guarantee). Test: init over an existing `0001-*.md` → `0002-adopt-agentic-factory.md`, commit `(ADR-0002)`, template present.
4. **The ADR flow contradicts itself between the hook, the vendored skill and the protocols.** The hook accepts only ADRs with `Status: accepted` and `Decided by:` (`factory-guardrails.mjs:105-107`); the vendored `skills/domain-modeling/ADR-FORMAT.md:9-15` ("That's it. An ADR can be a single paragraph", `Status` optional) is what the Front agent uses for ADRs (`docs/workflow.md:231`); and a *proposed* ADR can only be committed by citing a different accepted ADR in the message (experiment b3), which no document says. An Architect following the skill produces ADRs no commit can ever reference. Change: a "In this repo" paragraph at the top of the vendored `ADR-FORMAT.md` (note the local patch in `skills/SKILLS.md`) pointing to `docs/adr/0000-template.md`; one sentence in `templates/docs/architect-protocol.md:10` and `templates/AGENTS.md:36`: "to commit a new or proposed ADR, cite ADR-0001 (the adoption) in the message; once accepted, cite the ADR itself".
5. **`init` may create and commit a lockfile of the wrong package manager.** `bin/agentic-factory.mjs:49` picks the first of pnpm/npm/yarn on `PATH` when no lockfile exists and ignores `package.json` → `packageManager` (corepack) and `engines`; since round 5 that guess is no longer only a hook command but `<pm> install` run in the project, its lockfile committed with the adoption (`:156-165,201`) and a frozen install of that manager fixed in `commands.install`. A yarn or npm project on a machine with pnpm first gets `pnpm-lock.yaml` on `main` and `pnpm install --frozen-lockfile` in every wave. Change: in `detect()`, prefer the manager named in `packageManager` (and `volta`/`engines` if present) over the `PATH` order; print the chosen manager before question 10 with a hint to change it; `init` should refuse to run the install when the named manager is not installed. Test: `packageManager: "npm@10"` without a lockfile on a machine with pnpm → `package-lock.json`, `npm ci`.
6. **"Two rounds" is still hardcoded in three places, and the rendered guide ignores `maxRounds`.** `docs/reviews.md:12`, `site/index.html:115,157`, and `docs/workflow.md:137` / `docs/de/workflow.md:141` render into the project as "two by default" even when `maxRounds` is 3 (the guide goes through `render`, `bin/agentic-factory.mjs:181`). Change: `{{MAX_ROUNDS}}` in the two guide lines, "the configured number of rounds" in `docs/reviews.md`, and the intro page's figure labelled as the default.

This release is about running a factory unattended: an Orca bot as Front agent from the first question, a heartbeat that wakes the Controller reliably and says when it hangs, finished workers that are cleaned up, and a wave that merges exactly what was reviewed.

Existing configurations keep working. The exception is a project that edited its `CONTROLLER.md`: it keeps the old handbook, which no longer fits the new scripts (see "What changes for an existing project").

**New**
- **Onboarding with an Orca bot as Front agent** (#57):
  - `init` asks `hosts.frontAgent.kind` (`terminal`, the default, or `orca-bot`), for a bot `hosts.frontAgent.bot`, and `hosts.controller.controllerDir`. The same ids work in an `init --answers` file, and they are validated. `hosts.controller.controllerDir` proposes `~/controller-<project>` when `~/controller` already holds another project.
  - START.md has a section for the bot: create the bot in Orca, give its `SOUL.md` the line, then `init`, `start`, `doctor`.
  - An answered `commands.install` is kept as answered. For a project without a `package.json`, install is empty, and release commands come only from the project's own scripts.
- **One gate per project, a second factory on one host** (#59):
  - Each project has its own gate in its Controller directory (`<controllerDir>/gate` and `gate.mjs`). A project started with this version neither reads nor writes `~/.local/bin/gate`, so another factory's `start` can no longer overwrite it. Old shared files are left alone for older installations.
  - A gate called from another project's worktree is refused. `start` copies the gate, `gate.mjs` and `factory.config.json` to every other remote worker host, and `doctor` checks it per host.
  - `~/load.log` lines end in `project=<name>`. `stallwatch.mjs` reads only this project's workers.
  - What `start` writes on your machine is now documented in `docs/getting-started.md` ("What `start` writes on your machine"). Files shared between projects are written atomically.
- **The heartbeat** (#58, #64, #70):
  - On a local macOS Controller `start` schedules it as a launchd user job (cron elsewhere). When it cannot be scheduled, `start` says why and fails (exit 1); set `hosts.controller.heartbeat` to `false` or `"external"` if something else runs it. `doctor` and `status` say when it is not scheduled, or scheduled but not running.
  - The Controller's terminal is the one `start` created: `start` records its handle in `<controllerDir>/controller-terminal.txt`. A person's own agent session in the checkout is never taken for it. Only fixed text is typed into the Controller's terminal, never text a worker wrote.
  - It wakes the Controller for the inbox only when something is new. `inbox.md` is append-only: nothing rewrites it, the Front agent appends, and the Controller reads with `node inbox.mjs` and records what it handled with `node inbox.mjs --done`. A project with nothing new is woken at most every `hosts.controller.wake.idleMinutes` (default 30). A Controller that Orca reads as busy gets a one-line pointer after `hosts.controller.wake.busyPointerMinutes` (default 2).
  - A Controller that is busy but whose `status.md` and journal have not changed for `hosts.controller.hung.minutes` (default 25) is reported to the Front agent. The automatic restart is off by default: it happens only with `hosts.controller.hung.restart` set to exactly `true`. The Controller also starts itself fresh (`restart.mjs`) after a wave or when idle once its context use is above `hosts.controller.restart.contextPercent` (default 50).
  - Nothing is typed while a confirmation question is on the screen (`hosts.controller.wake.dialogPatterns`). After `wake.dialogHoldMinutes` (default 15) the Front agent is told once.
  - A healthy idle Controller is no longer reported stale: the stale limit is at least `wake.idleMinutes` + 15 (45 by default), for the bot watch and the terminal watch.
- **Finished workers are cleaned up** (#54, #63):
  - A worker counts as finished by its dispatch state in Orca (`succeeded`, `failed`, `stopped`), also while its agent still sits at the prompt. Cleanup, the capacity cap and the heartbeat use that. Anything Orca does not report as finished counts as busy.
  - Cleanup releases a finished worker only when its worktree is clean and its branch is merged or pushed. `node keep.mjs <key>` keeps one for you (`--off` undoes it).
  - `node cleanup.mjs` removes nothing without `--apply`. Without it, it prints an inventory and exits 3 when there is work it did not do. `--prune-remote` leaves `status-wave-<n>` branches to you; the inventory lists them.
- **The wave** (#62, #68):
  - For code, the wave always runs the full gate itself before it pushes. No earlier result is accepted. `GATE` for the wave must be an absolute path to the project's own gate.
  - It merges exactly the commit that was reviewed. After each reviewer's verdict the Controller runs `node reviewed.mjs <task> <review-branch> <review-sha>`, which records that commit. `wave.mjs` then refuses to start for a task without a record (`WAVE-NOT-STARTED`), and the wave stops as a whole (`WAVE-STOPPED`, naming both commits) when a branch moved after its review.
- **Documentation-only tickets and the formatter, both opt-in** (#52, #65):
  - With `docsOnly.enabled` set to `true` (an `init` question), a ticket that declares `Level: 1` and `Documentation only: yes` skips its Tester round when `node docsonly.mjs <task> <branch>` finds that the branch changes only documentation (`docsOnly.paths`). That saves the Tester round. It does not save the gate: the wave still runs the full gate for such a ticket.
  - `commands.formatStaged` runs a formatter on the staged files at commit and stages the result.
- **Bounded review rounds** (#53): `reviews.maxRounds` is a whole number of at least 1. `mkspec test --round <n>` refuses a round beyond it, and `mkspec reeval` is the way out. From round 2 the Tester re-checks the earlier blockers and majors and the rework since, not the whole branch again.
- **Every command and script answers `--help` and refuses unknown arguments** (#55). `--help` prints the usage and does nothing else; an unknown option exits 2 before anything runs. A call like `cleanup.mjs --on=server` that used to run silently on the default host now exits 2.

**Fixed**
- `wait.mjs` crashed on the first worker event, because Orca delivers the payload as an object (#53, #29). It now reads both forms, prints every message, and no longer cuts bodies or output.
- The push gate rejected a passing review when the `Reviewed commit:` SHA was in backticks (#61, #60). A backticked SHA is accepted now; everything accepted before still is.
- `agentic-factory start --help` and `update --help` ran the command (#55, #24, #38).
- `start` overwrote the shared `~/.local/bin/gate` of other projects on the same host (#59, #25).
- `stallwatch.mjs` no longer reads other projects' worker terminals on a shared host (#59).
- The heartbeat finds a Controller terminal that Claude Code or pi renamed, and no longer writes "Controller is not running" when Orca's terminal list itself failed (#58). The cron and launchd jobs carry node's directory on their PATH.
- Cleanup now removes worktrees of workers that finished while their agent still sat at the prompt, and capacity no longer counts them (#54).
- The commit hook's message for a commit with only documentation staged no longer reads like the docs-only gate path (#62).
- The bot watch is woken when its precheck fails with an error, once per distinct error (#55). An unknown bot creates no watch directory (#63).

**What changes for an existing project**
Run `agentic-factory update`, then `start`.
- `update` re-renders the project; a file you changed is kept, and the new version lands in `.factory/new/`. `start` copies the new Controller and Front agent bundles (it now includes `inbox.mjs`, `restart.mjs`, `front-notice.mjs`, `reviewed.mjs`, `keep.mjs` and `cli.mjs`), schedules the heartbeat, and gives the project its own gate.
- **A `CONTROLLER.md` you edited stays, and the new one lands in `.factory/new/.factory/controller/CONTROLLER.md`.** Take the new one: merge it, then run `start`. Until then:
  - cleanup removes nothing (the old handbook calls it without `--apply`, so every cycle exits 3);
  - every non-empty inbox keeps waking the Controller, because it does not know `inbox.mjs --done`, and a restarted Controller does not know `restart.md`;
  - a wave stops at `WAVE-NOT-STARTED`, because the old handbook never records reviews with `reviewed.mjs`.
  `update` and `start` print a WARNING when the installed handbook calls cleanup without `--apply` or does not mention `inbox.mjs --done` or `restart.md`; `doctor` and `status` report the same, and report removable work that has waited longer than `cleanup.pendingWarnMinutes` (default 30). An unedited `CONTROLLER.md` is replaced by `update`. A Controller session that is already running keeps the old text until it re-reads the file.
- **The gate moves from `~/.local/bin` to the project's Controller directory.** `start` copies it. The shared files stay where they are; `doctor` and `status` tell you when a leftover one is there and unused. A worker host that ran the gate by name needs the Controller directory's `gate` path instead.
- **`inbox.md` must no longer be emptied or edited by hand.** A file whose start no longer matches what was handled counts as all new. Take lines off by recording them with `node inbox.mjs --done`.
- **Tickets reviewed before the update:** their review has no recorded commit. The wave stops with a one-time message: the review reported no SHA, so it cannot be recorded. Send the task back to review (a new Tester round with `mkspec test`, or `mkspec reeval` where the round limit applies), then record it with `reviewed.mjs`.
- **Waking changes for every project.** An idle project is woken every 30 minutes (`wake.idleMinutes`), more often than the earlier hourly wake. Set it to 60 to keep it hourly. The hang report, the health line and the pointer line are on; only the automatic restart is off.
- **A config that still says `hosts.frontAgent.staleMinutes: 25`** has its limit raised to `wake.idleMinutes` + 15. `doctor` prints `stale limit: …`, and the watch says so once with a `CONFIG:` note. Set it to `null`.
- **`update` leaves the heartbeat schedule alone; `start` replaces it.** An older cron line is refreshed, a hand-written one is kept, and an existing cron line on macOS is kept (no second job).
- **Start can now fail:** it exits 1 when the heartbeat cannot be scheduled.
- **A remote worker host gets the gate bundle** (`gate`, `gate.mjs`, `factory.config.json`) from `start`; a failure fails `start`.
- Scripts that were called with an unknown or misspelled argument now exit 2 instead of running.

**Tested for real, and not**
- Three end-to-end runs on macOS, with a Claude Code Controller and an Orca bot as Front agent. The last one ran on this release's state minus its last small fix (#70). In it four tickets reached main, two of them through the documentation-only path. Every wave ran the full gate for code, one wave stopped because a commit was pushed after its review, and cleanup removed the finished workers with `--apply`.
- Not run for real: the automatic restart of a hung Controller (off by default), a remote Controller host, and a Controller on another agent CLI than Claude Code. The documentation-only wave on a remote worker host and the formatter with a real formatter (`prettier`) were tested with stand-ins only. Everything else in the test suite runs against fakes of Orca, ssh, `launchctl`, `crontab` and `gh`.

**Known limits**
- **An idle Controller with a running `wait.mjs` is read as busy by Orca.** A new inbox line then reaches it as a pointer after a few minutes. Ready tickets alone do not wake it until some new event comes. In the last run the Controller had to be woken by hand once, after 12 minutes. The cause is not understood. If you run unattended, watch for this.
- Nothing creates the integration worktree for the first wave (#28); in the last run the Controller created it itself.
- The Controller reads the machine-wide Orca mailbox and sees the subjects of other projects' messages on a shared host.
- `status` can report an open question when a "Needs" section says `none (…)`.
- The review gate is a local hook (F01), and a wave does not check that a verify command left the hooks in place (F46). A `wait.mjs` batch can be lost when the CLI dies after Orca marked it handled (F53). The read grants for lean-ctx and context-mode are written for a local Controller only (F52). The copy to a remote host ran against a fake `ssh` only (F43). Fixed `/tmp` file names in the wave scripts mean two Controllers on one host can overwrite each other's wave logs (F17).
- `start` on the Controller's own host still copies over ssh to itself and does not know a server-side Front agent (#39).
- Still open that you can hit: the trust-folder dialog at the first start is named in a hint but not answered for you (#23); `wavewait.mjs` waits out its 90 minutes when the wave's terminal is already closed (#32); the secret filter can drop whole worker messages that mention words like `token` (#31); `orcaRepoId` in the tracked config is specific to one host (#26).
- `agentic-factory start --help` and `update --help` (#24, #38) and the shared gate (#25) are fixed in this release.

After updating, run `agentic-factory update` in each project, then `start`, then `doctor`.

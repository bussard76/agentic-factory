# Debt register of the factory itself

Known limits of agentic-factory, recorded the way the factory records debt in a project: category, origin, risk, proposal, size. Worked off in a hardening phase. Items come from `docs/reviews/factory-review-*.md`.

| ID | Category | Origin | Risk | Proposal | Size | Status |
|---|---|---|---|---|---|---|
| F01 | security | review 1, #14 | the pre-push review gate is a local hook: a different client or a self-authored `Verdict: pass` file bypasses it; the reviewer is not identified | protect `main` server-side (branch protection plus a CI job that re-checks review coverage) and record the reviewer's identity (dispatch id, agent, model) in the findings file; describe local hooks as advisory | M | open |
| F02 | security | review 1, #13 | the staged-secret scan knows a handful of patterns, skips binaries, exempts `.env.example` | use a maintained scanner (e.g. gitleaks, pinned) behind the same hook, with a scoped allowlist; keep the built-in patterns as a fallback | M | open |
| F03 | tests | review 1, #12 | the test-count guard counts regex matches in test files; a dummy test keeps the count, unsupported frameworks are not counted | treat it as a heuristic in the docs (done), add the project's runner result (`--reporter json`) as the second signal, require review of test deletions | M | open |
| F04 | tests | review 1, #11 | a project with no configured verify command passes a wave with no tests (the wave now refuses an empty `commands.verify`) | `init` refuses to finish without a verify command or an explicit recorded "no tests yet" decision | S | open |
| F05 | tests | review 1, #23 | no automated tests for the factory itself beyond `test/smoke.test.mjs` | end-to-end tests for update, hooks on edge cases, wave errors, both steering modes, terminal runner | M | open |
| F06 | edge-case | review 1, #18 | model calibration counts review events, not finished tasks, and does not join worker model to review | aggregate per task and tier; carry `model`/`role` from the `start` event into `review` events in the Controller loop | S | open |
| F07 | edge-case | review 1, #22 | `gate` measures the ticket queue (fixed); FIFO fairness holds within one host only | document per-host fairness; nothing to do until gates span hosts | S | open |
| F08 | security | review 1, #15 | the preview updater runs `git clean` in the configured clone and links the project's real `.env` | refuse to run in a non-dedicated clone (marker file), prefer a demo-only env file; document the boundary (human preview may use real environment, automated tests never) | S | open |
| F09 | edge-case | review 1, #8; review 2, #14 | terminal-runner start does not verify the remote launch, and single-quotes `~` in remote paths | expand paths with `$HOME` on the target, return and check the remote pid; persist the worker only after a verified start (experimental runner) | S | open |
| F10 | tests | review 2, #1/#4/#6; review 3 | the smoke test did not cover the real wave script, a wave after `main` moved, `wait.mjs` defaults, ghost workers in capacity, or a second `init` run | tests added for all of these (`test/smoke.test.mjs`) | S | done |
| F11 | edge-case | review 3, #5; review 4, #2 | hooks run the detected package manager on every code commit; a wrong guess blocks commits | `init` picks the lockfile's manager, else the first installed of pnpm/npm/yarn, prints the commands, uses a plain install without a lockfile and ignores `node_modules/`; `doctor` could additionally verify that `commands.lint`/`typecheck` run | S | open |
| F12 | security | review 4, #5 | any accepted ADR satisfies the protected-file hook (`ADR-0001` passes for every later change) | dependency lists are no longer hook-protected (the Architect decides level 2); the referenced ADR must now be accepted and carry `Decided by:`; still open: require the ADR to name the path it covers | S | open |
| F13 | edge-case | review 5, #6 | the hooks' lint can install (pnpm) and leave an untracked lockfile when the project had none | `init` now runs one install and commits the lockfile with the adoption; projects adopted earlier commit their lockfile by hand | S | done |
| F14 | security | review 6, #1; review 7, #4 | `init --keep-own-hooks` (`hooks.mode: own`) leaves the review gate to the project's own hooks; the factory cannot verify that (the rendered docs say so) | `doctor` could run a synthetic unreviewed push against a scratch remote to prove the own gate bites | S | open |
| F15 | security | review 9, #4 | husky v9: `.husky/_` is generated by the install, so a fresh clone or worker worktree has no hooks until the install ran; `HUSKY=0` skips husky-run hooks entirely | `doctor` now fails when the hooks directory is missing and `AGENTS.md`/`CONTROLLER.md` forbid `HUSKY=0`; still open: worker specs should start with the install command, and F01 (server-side protection) covers the bypass class | S | open |
| F18 | edge-case | review 12, #1 | a repository without `package.json` still gets `commands.install = <pm> install` as default, so a Python/Go/docs project's first wave fails `INSTALL-FAILED` unless the human empties the answer | `detect()` returns `install: ""` without `package.json` and `init` prints `install: (none)` | S | open |
| F19 | edge-case | review 12, #2 | the stale-bare probe checks the bare's `HEAD` symref; with stock git (`HEAD` → unborn `master`) and a project on `main`, a start-over without a commit still adopts the stale bare (init exits 1, but origin, hooks and config stay) | probe `git -C <bare> show-ref --heads`; on a failed adoption push remove origin and print the `rm -rf <bare>` remedy with the last stderr line | S | open |
| F20 | docs | review 12, #3 | own mode renders "the rule below" into AGENTS.md, the ADR and dev-workflow.md where no rule follows; the global-hooks NOTE claims init sets a path it does not set with `--keep-own-hooks` | reference `docs/review-protocol.md` ("Push enforcement") by name; skip the NOTE in own mode | S | open |
| F21 | docs | review 12, #4 | `docs/de/workflow.md` tools table lacks the `mkspec.mjs` role list and the `skills/SKILLS.md` pointer of the English table | add both code spans | S | open |
| F22 | onboarding | review 12, #5 | files left untracked after the adoption (e.g. a `lint.js` that `commands.lint` runs) are named in a NOTE but not in the checklist; a worker's first commit then fails in `pre-commit` | checklist step "Commit <files>" when anything is untracked | S | open |
| F23 | robustness | review 12, #6 | `wait.mjs --hours` sleeps a fixed 30 s after a failed Orca check, so a tiny window waits 30 s; the smoke test comment says ≈2 s | `Math.min(30000, end - Date.now())` in both branches; fix the comment | S | open |
| F24 | onboarding | agent-entry review, #1 | `init --answers` validates choices only: a non-numeric port or review-round count, an empty ssh alias and a mistyped id pass silently; an answers file without `rules.confirm` confirms the hard rules by default | validate text answers per id (numbers, non-empty), reject unknown ids, require `rules.confirm` in `--answers` mode | S | closed |
| F25 | onboarding | agent-entry review, #2 | without a remote, `--print-questions` recommends a sentence for `project.repo`; an agent that takes the recommendation stores it as the repo | compute the deterministic `local:<bare path>` in both modes, or drop the question when init creates the remote | S | closed |
| F26 | robustness | agent-entry review, #3 | remote `start`: `pgrep -f loadlog.sh` matches its own ssh shell, so the load log is never started on the Controller's host while `start` reports ok | `pgrep -f "[b]ash loadlog.sh"` or a pid file. | F27 | robustness | agent-entry review, #4 | remote `start`: the Orca worktree selector carries an unexpanded `~` (`path:~/projects/<name>`), and the environment name defaults to the host name | resolve the absolute path over ssh first; record the saved Orca environment name at init | S | closed |
| F28 | edge-case | agent-entry review, #5 | the "Needs <human>" parser counts a table header as an open item and drops real items that contain "none" | skip a header row before a `|---` line; treat only a bare none/nothing/keine as empty | S | closed |
| F29 | edge-case | agent-entry review, #6 | `status` in github-issues mode does not know the factory's own `needs-human` label | align the label list with `controller/steering/issues.mjs`; count `needs-human` issues as open questions | S | closed |
| F30 | edge-case | agent-entry review, #7 | Controller terminal detection is a substring match, so project `a` sees `proj-a · Controller` as its own | parse the terminal list and compare the title exactly | S | closed |
| F31 | docs | agent-entry review, #8 | the docs do not say that every later session starts with the same sentence; the manual `cp -R .factory/controller ~/controller` nests a copy when the directory exists | one sentence in EN and DE; `cp -R .factory/controller/. ~/controller/` | S | closed |
| F32 | edge-case | fixes review, #2 | an exited Controller terminal still counts as running, so `start` does not recreate the session | filter `status !== "exited"` as capacity, cleanup and stallwatch do | S | open |
| F33 | onboarding | fixes review, #3 | `--answers` validates ids against a static list, not against the questions actually asked; answers to unasked questions pass silently and the list must be kept in sync by hand | after the question loop, reject keys not in `asked` | S | open |
| F34 | edge-case | fixes review, #4 | near-bare markers like `- None.` or `- nothing open` count as open questions and raise phase decisions | strip a trailing dot; accept none/nothing/keine followed by up to two words | S | open |
| F35 | docs | fixes review, #5 | the new remote question `hosts.remote.orcaEnvironment` is not in docs/onboarding.md (EN and DE); with the empty default a remote `start` fails until it is set | one cell in EN and DE | S | open |
